AI Agent कैसे बनाएँ — Gemini API से, जो सोशल मीडिया और फ़ोन चलाए

एक ऐसा एजेंट जो आपकी बात समझे, वीडियो डिलीट करे, Instagram · YouTube · Facebook · X मैनेज करे, और आपके ही Android फ़ोन को कंट्रोल करे — सब कुछ ऑफ़िशियल API से, बिना किसी ख़तरनाक जुगाड़ के।

Gemini API Function Calling Official APIs Android Automation हिंदी गाइड

01 AI Agent क्या है — और कैसे काम करता है

सबसे पहले यह समझ लो: एजेंट कोई जादू नहीं है। यह एक प्रोग्राम है जो Gemini जैसे मॉडल से बात करता है, और मॉडल के कहे मुताबिक़ असली काम (API कॉल, फ़ाइल, फ़ोन) करता है।

साधारण चैटबॉट सिर्फ़ जवाब लिखता है। Agent जवाब देने के साथ-साथ काम भी करता है — जैसे "मेरा पुराना वीडियो डिलीट कर दो" कहने पर असल में वीडियो डिलीट हो जाता है। इसके लिए मॉडल को tools (औज़ार) दिए जाते हैं, और मॉडल ख़ुद तय करता है कौन-सा औज़ार कब इस्तेमाल करना है। इसे Function Calling कहते हैं।

1
आपकी बात"X पर आज का पोस्ट डाल दो और यह पुराना YouTube वीडियो हटा दो" — यह प्रॉम्प्ट मॉडल तक जाता है।
2
मॉडल सोचता हैGemini समझता है कि इसके लिए दो औज़ार चाहिए: post_to_x और delete_youtube_video — और तर्क (arguments) बनाता है।
3
आपका कोड असली काम करता हैमॉडल ख़ुद कुछ नहीं करता — वह सिर्फ़ बताता है कि कौन-सा function चलाना है। असली API कॉल आपका प्रोग्राम करता है।
4
नतीजा वापस मॉडल कोAPI का जवाब ("वीडियो डिलीट हो गया", "पोस्ट लाइव है") मॉडल को भेजा जाता है।
5
आपको साफ़ जवाबमॉडल सब जोड़कर कहता है: "हो गया — पोस्ट लाइव है और पुराना वीडियो हट गया।" यह चक्र दोबारा चल सकता है (loop)।
यही "loop" एजेंट की जान है

अगर आप Python में एक loop लिख सकते हैं, तो आप एक एजेंट बना सकते हैं। यह पूरा तंत्र इसी एक बात पर टिका है — मॉडल बताता है, आपका कोड चलाता है, नतीजा वापस मॉडल को जाता है।

02 Gemini API सेटअप — पहला कदम

Gemini API का इस्तेमाल शुरू करने के लिए एक key चाहिए और एक छोटी Python लाइब्रेरी। Google AI Studio से key फ़्री में मिल जाती है।

स्टेप 1

API Key लो

Google AI Studio (aistudio.google.com) पर जाओ, Google अकाउंट से लॉगिन करो, "Get API key" पर क्लिक करो। फ़्री tier में रोज़ कुछ हज़ार requests मिलती हैं — सीखने और छोटे काम के लिए काफ़ी है।

स्टेप 2

SDK इंस्टॉल करो

टर्मिनल में एक कमांड। Python 3.10+ रखना।

स्टेप 3

Key सुरक्षित रखो

Key को कभी कोड में सीधे मत लिखो। उसे environment variable में रखो — यही सुरक्षित तरीक़ा है।

terminal — सेटअप
# लाइब्रेरी इंस्टॉल करो
pip install google-genai

# API key को environment variable में रखो (कोड में कभी नहीं!)
export GEMINI_API_KEY="यहाँ-अपनी-key-डालो"
कभी न करने वाली गलती

API key या password को सीधे कोड या किसी public GitHub पर मत डालो। हमेशा .env फ़ाइल या environment variable इस्तेमाल करो, और .env को .gitignore में डालो।

03 एजेंट का दिल — Function Calling

अब सबसे ज़रूरी हिस्सा। हम एक छोटा-सा function बनाते हैं, उसकी "definition" मॉडल को देते हैं, और एक loop चलाते हैं जो मॉडल के कहे मुताबिक़ काम करता है।

Function Declaration मतलब मॉडल को यह बताना कि यह function क्या करता है, कौन-से इनपुट लेता है। मॉडल ख़ुद function नहीं चलाता — वह बस कहता है "यह function इन arguments के साथ चलाओ", और असली काम आपका कोड करता है।

agent.py — पूरा काम करने वाला ढाँचा
from google import genai
from google.genai import types

client = genai.Client()

# --- 1) असली काम करने वाला function (जैसे YouTube डिलीट) ---
def youtube_delete(video_id: str) -> dict:
    """एक YouTube वीडियो को डिलीट करता है (ऑफ़िशियल API से)।"""
    # यहाँ YouTube Data API का DELETE कॉल होगा
    return {"status": "deleted", "video_id": video_id}

# --- 2) मॉडल को बताने के लिए definition ---
youtube_delete_tool = {
    "type": "function",
    "name": "youtube_delete",
    "description": "किसी YouTube वीडियो को डिलीट करता है",
    "parameters": {
        "type": "object",
        "properties": {
            "video_id": {"type": "string", "description": "वीडियो का ID"}
        },
        "required": ["video_id"],
    },
}

# --- 3) मॉडल से पूछो ---
resp = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="मेरा वीडियो abc123 डिलीट कर दो",
    config=types.GenerateContentConfig(tools=[youtube_delete_tool]),
)

# --- 4) अगर मॉडल ने function माँगा, तो चलाओ ---
if resp.function_calls:
    for call in resp.function_calls:
        print("Tool:", call.name, "Args:", call.args)
        # यहाँ असली function चलाओगे, e.g. youtube_delete(**call.args)
else:
    print(resp.text)
ज़रूरी बात

Parallel + Compositional

Gemini एक ही बार में कई functions माँग सकता है (parallel), और एक function का नतीजा दूसरे में इस्तेमाल कर सकता है (compositional) — यानी असली मल्टी-स्टेप काम।

बेहतर तरीक़ा

Loop में बदलो

ऊपर वाले कोड को while loop में डालो: function चलाओ → नतीजा मॉडल को भेजो → मॉडल फिर सोचे। यही "agentic loop" है।

सुरक्षा

हर काम से पहले पूछो

डिलीट/पोस्ट जैसे काम से पहले user से confirm लो। System instruction में लिखो: "बिना पुष्टि के कोई डिलीट या पोस्ट न करो।"

04 सोशल मीडिया कंट्रोल — ऑफ़िशियल API

हर प्लेटफ़ॉर्म का अपना ऑफ़िशियल API है। इन्हीं से पोस्ट, शेड्यूल और डिलीट होता है — कोई "हैक" नहीं, बस सही OAuth और permission।

प्लेटफ़ॉर्मAPIक्या-क्या कर सकते होमुख्य शर्त
YouTube youtube/v3 वीडियो अपलोड, मेटाडेटा बदलना, वीडियो डिलीट करना OAuth 2.0 scope चाहिए। डिलीट = 50 quota units; अपलोड = अलग bucket (रोज़ ~100)।
Instagram graph.facebook.com फ़ोटो / Reels / Story पब्लिश, कैरोसेल पोस्ट सिर्फ़ Business/Creator अकाउंट। पहले media container बनाओ, फिर publish। 24 घंटे में 50 पोस्ट की सीमा।
Facebook Page Pages API Page पर पोस्ट, शेड्यूल, मीडिया, डिलीट Page access token + pages_manage_posts permission। शेड्यूल 10 मिनट से 30 दिन के बीच।
X (Twitter) api.x.com/2 ट्वीट, थ्रेड, मीडिया अपलोड Free tier सिर्फ़ ~500 पोस्ट/महीना (read बहुत कम)। गंभीर काम के लिए Basic ($200/महीना) चाहिए।
उदाहरण — YouTube वीडियो डिलीट (REST)
# OAuth token मिलने के बाद:
DELETE https://www.googleapis.com/youtube/v3/videos?id=VIDEO_ID
Authorization: Bearer ACCESS_TOKEN

# सफल होने पर 204 No Content मिलता है (कोई body नहीं)
उदाहरण — Instagram पोस्ट (2 कदम)
# कदम 1: media container बनाओ (image public URL पर होनी चाहिए)
POST /<IG_ID>/media
  ?image_url=https://example.com/pic.jpg
  &caption=मेरा नया पोस्ट
  &access_token=TOKEN

# कदम 2: container को publish करो
POST /<IG_ID>/media_publish
  ?creation_id=CONTAINER_ID
  &access_token=TOKEN
अपने एजेंट में कैसे जोड़ेंगे

हर प्लेटफ़ॉर्म के लिए एक-एक function बनाओ — जैसे post_to_instagram(caption, image_url), post_to_x(text), delete_youtube(video_id)। इन सबकी definitions Gemini को दो, और एजेंट आपकी बात से ख़ुद तय करेगा कि कौन-सा चलाना है।

05 फ़ोन कंट्रोल — Android को सुरक्षित तरीक़े से चलाना

अपने ही फ़ोन को कंट्रोल करने के दो साफ़-सुथरे रास्ते हैं — दोनों बिना root, बिना कोई सिस्टम तोड़े। स्क्रीन ऑन/ऑफ़, टैप, ऐप खोलना-बंद करना — सब हो सकता है।

तरीक़ा A

Accessibility Service

Android का ऑफ़िशियल तरीक़ा — इसी से बड़े ऑटोमेशन ऐप (Tasker, MacroDroid) UI पर क्लिक/टैप करते हैं। आप ख़ुद एक ऐप बनाकर इसे जोड़ सकते हैं, या तैयार ऐप इस्तेमाल कर सकते हैं।

तरीक़ा B

ADB Wireless Debugging

Android 11+ में फ़ोन ख़ुद से ADB daemon चलाता है। आप फ़ोन से ही (या PC से) कमांड भेज सकते हो — टैप, keyevent, screenshot, ऐप बंद करना। root की ज़रूरत नहीं।

तरीक़ा C

तैयार ऐप + AI

MacroDroid / Tasker में वेबहुक और "AI LLM Query" action है। आपका Gemini एजेंट webhook भेजता है, और फ़ोन पर macro चल जाता है — बिना ऐप बनाए।

ADB — काम की कमांड (Wireless Debugging चालू होने पर)
# फ़ोन से फ़ोन को जोड़ो (एक बार pairing code से)
adb pair 127.0.0.1:<PAIRING_PORT> <6-अंकों-का-कोड>
adb connect 127.0.0.1:<SESSION_PORT>

# स्क्रीन ऑन/ऑफ़ और लॉक
adb shell input keyevent 26     # Power (स्क्रीन ऑन/ऑफ़)
adb shell input keyevent 224    # Wake up (स्क्रीन जगाओ)
adb shell input keyevent 223    # Lock screen

# टैप / स्वाइप / टाइप
adb shell input tap 540 1200
adb shell input swipe 540 1800 540 900 300
adb shell input text "Hello"

# स्क्रीनशॉट और ऐप बंद करना
adb shell screencap -p /sdcard/s.png
adb shell am force-stop com.instagram.android
अपने Gemini एजेंट से फ़ोन चलाना

एक function बनाओ जो shell कमांड चलाए — जैसे phone_command(cmd: str)। Gemini आपकी बात ("फ़ोन की स्क्रीन बंद कर दो") को सही कमांड में बदल देगा। लेकिन सुरक्षा के लिए सिर्फ़ एक allowed-list रखो (सिर्फ़ कुछ तय कमांड ही चलें), कोई भी कमांड नहीं।

06 "Android Bypass" की सच्चाई — इसकी ज़रूरत ही नहीं

आपने पूछा था कि "Android सिस्टम bypass कैसे करें"। ईमानदारी से: ऐसा करने की ज़रूरत नहीं है, और यह नुक़सानदेह है। आइए समझें क्यों।

जो भी काम आप चाहते हैं — स्क्रीन ऑन/ऑफ़, टैप, ऐप मैनेज करना — वह सब Accessibility Service और ADB से ऊपर वाले सेक्शन में ही हो जाता है, बिना कुछ "तोड़े"। "Bypass" यानी security तोड़ना या root करना, तब चाहिए जब आप ऐसा काम करना चाहो जो Android जान-बूझकर रोकता है (जैसे किसी और का लॉक तोड़ना, DRM हटाना)। ये काम:

ख़तरा

Root करने के नुक़सान

वारंटी ख़त्म, बैंकिंग/UPI ऐप्स काम करना बंद कर देते हैं, malware का डर बढ़ जाता है, OTA अपडेट टूट सकते हैं, और फ़ोन ब्रिक (बेकार) हो सकता है।

गैरक़ानूनी

दूसरे के डिवाइस पर

किसी और के फ़ोन/अकाउंट को बिना इजाज़त bypass करना या उसका डेटा निकालना अपराध है। हम इसमें किसी भी तरह की मदद नहीं कर सकते।

सही रास्ता

ऑफ़िशियल = सुरक्षित

Accessibility + ADB + ऑफ़िशियल APIs से वही सब मिलता है जो आप चाहते हैं, वह भी सुरक्षित और बिना रिस्क। यही "कोई ख़तरा न हो" वाली शर्त पूरी करता है।

साफ़ बात

मैं Android की security bypass करने, किसी का लॉक तोड़ने, या ऐसी कोई चीज़ बनाने में मदद नहीं कर सकता जिससे किसी और को नुक़सान हो। लेकिन आपके अपने फ़ोन को सुरक्षित तरीक़े से ऑटोमेट करने का पूरा रास्ता — Accessibility Service, ADB, MacroDroid/Tasker + Gemini — ऊपर दिया है और वह काफ़ी शक्तिशाली है।

07 30-दिन का रोडमैप — शून्य से एजेंट तक

हर हफ़्ते एक-एक चीज़ जोड़ो। जल्दबाज़ी मत करो — हर हफ़्ते का एक साफ़ लक्ष्य है।

हफ़्ता 1

बुनियाद

AI Studio से key लो, google-genai इंस्टॉल करो, एक साधारण "Hello" वाला Gemini कॉल चलाओ। समझो कि key कैसे सुरक्षित रखनी है।

हफ़्ता 2

पहला function

एक ऐसा function बनाओ जो कुछ असली करता हो — जैसे फ़ाइल पढ़ना/लिखना, या weather API। उसकी definition मॉडल को दो और function-calling चलाओ।

हफ़्ता 3

एजेंट loop + confirm

Function-calling को while loop में डालो। System instruction में सुरक्षा-नियम जोड़ो (किसी काम से पहले पूछो)। अब यह असली एजेंट है।

हफ़्ता 4

सोशल मीडिया जोड़ो

एक प्लेटफ़ॉर्म से शुरू करो (YouTube सबसे आसान)। OAuth करो, एक function बनाओ (जैसे अपना वीडियो डिलीट करना), और एजेंट से चलवाओ।

आगे

फ़ोन कंट्रोल जोड़ो

ADB wireless या MacroDroid webhook जोड़ो, एक allowed-list वाला phone_command function बनाओ। पहले छोटे काम (स्क्रीन ऑफ़) से टेस्ट करो।

08 सेफ़्टी चेकलिस्ट — कोई ख़तरा न हो

करो

ये ज़रूर करो

  • Key/secret को environment variable में रखो
  • हर डिलीट/पोस्ट से पहले user से confirm लो
  • phone_command में सिर्फ़ allowed-list कमांड
  • ऑफ़िशियल API और OAuth ही इस्तेमाल करो
  • छोटे टेस्ट अकाउंट पर पहले आज़माओ
मत करो

  • कोड में API key hardcode मत करो
  • किसी और के डिवाइस/अकाउंट पर काम मत करो
  • Security bypass / root जैसी चीज़ें मत करो
  • बिना rate-limit वाले पोस्ट-लूप मत बनाओ
